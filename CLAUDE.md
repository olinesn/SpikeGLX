# Notes for Claude sessions working on this SpikeGLX fork

This is olinesn's fork of `billkarsh/SpikeGLX`. Its own work is an unofficial offline build for
Apple Silicon Macs (`SpikeGLX_NISIM.app`); `macos/README.md` describes it. `linux/README.md`
describes the same build for Linux on Arm (aarch64), packed as an AppImage.

## Branches

- **`master` is upstream, unchanged.** Never commit or push to it; it is updated only with
  GitHub's Sync fork, so it always equals `billkarsh/SpikeGLX` master.
- **`dev` is the fork's line** (the default branch). Every change goes in by pull request to
  `dev`, from a branch of its own. `dev` requires a PR and two checks, `macOS arm64 build` and
  `Linux arm64 build`; this applies to admins too. The user merges; never merge, and never
  suggest a merge or an order.
- **Taking a new upstream version:** a PR to `dev` that merges `master` after a Sync fork.
- **Keep upstream fixes in their own commits**, so one can go upstream by itself.
- **Sending a fix upstream** (only when the user asks; post nothing on `billkarsh/SpikeGLX`
  otherwise). Upstream takes issues and pull requests. Branch `fix-<what>` off `master`
  (upstream's tree, not `dev`), cherry-pick the fix's one commit, check that
  `git patch-id --stable` matches the commit that was tested, and drop fork-only wording from its
  message. Open the PR to `billkarsh/SpikeGLX` `master`, with `Fixes #<n>` when an upstream issue
  exists. `dev` keeps its own copy of the fix until upstream has one.
- **What upstream does with a fix:** pull requests aren't merged. Upstream writes the fix in its
  own commit and closes the issue and the PR unmerged ("Done, in <version>"), as with this fork's
  first four (upstream #54–#57, version 20261112). The next merge of `master` into `dev` then
  conflicts wherever `dev` has its own copy: compare the two line by line, keep upstream's version
  where it fixes the same bug, and update `macos/README.md` in the same PR.

## Editing upstream files

- Change as little as possible, and say why in the commit.
- The repo stores text with CRLF line endings (`.gitattributes`: `* text eol=crlf`). Keep CRLF
  in upstream files. `macos/` and `linux/` have their own `.gitattributes` (LF) because their
  scripts run on macOS and Linux.

## Keep macos/README.md and linux/README.md current

- **Same PR.** A PR that changes a build step, a version, a test or a known issue also updates
  `macos/README.md`, or `linux/README.md` for the Linux build. Say in the PR description what
  changed in the docs, or that nothing in them needed to.
- **`.github/workflows/macos-arm64-offline.yml`** builds, checks and smoke-tests the app on every
  PR and every push to `dev`, and uploads it. Run `macos/smoke_test.py` on your own build too:
  it opens a window for a few seconds. On Linux, run `linux/smoke_test.py` on the program or the
  AppImage; it needs an X display.
- **`.github/workflows/linux-arm64-offline.yml`** does the same for the Linux build on GitHub's
  Arm runners (`ubuntu-24.04-arm`), running the smoke test on the program and the AppImage
  under Xvfb. `dev` requires it too, so a branch cut from `dev` before this workflow was on it
  never gets the check, and its PR can't merge until the branch is brought up to date with `dev`.

## Pull request descriptions

Start with `*Auto-generated by Claude Code, not typed by olinesn.*`, then `## In short`
(plain words: what changes and what a user notices), `## What changed`, `## Checked`
(what was tested, and what wasn't) and `## Docs`. End with
`🤖 Generated with [Claude Code](https://claude.com/claude-code)`. Commit titles are plain
words too.

## Everything here is public

The repo is public. No IP addresses, host names, user names, paths from someone's machine, or
lab or institution names in files, commits, PRs or issues.
